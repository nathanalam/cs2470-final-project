# Milestones M3-M5: the GPU sweep

Brief for every agent working on M3. Read it whole before starting, along with `AGENTS.md` and the M1-M2
brief (`docs/milestones/M1-M2.md`, for what already exists). The plan doc is "Modal + Slurm Pipeline and GPU
Sweep Plan"; this file is what you need to act.

## Goal

- **M3 (sweep infrastructure):** one config fans out across five Modal GPUs (L4, A100-80GB, H100, H200, B200);
  every runtime the 11 roofline models need has a Modal image; every GPU has datasheet peaks; the report draws
  several GPUs.
- **M4 (the sweep):** the 11 roofline models (200 questions each, Nathan's `roofline_l4*` settings) on all five
  GPUs, H100 and H200 first; OpenJev JEVal smoke and shape sweep on the 80 GB GPUs. Coordinator only.
- **M5 (report):** regenerated report and IV/DV CSV, findings rewritten around the cross-GPU results.

## Frozen contracts (do not change; ask the coordinator)

- `src/s1/launch/modal_images.py`: `RUNTIMES`, `check_runtime(runtime)`, `describe(runtime, *, openjev)`,
  `image(modal, *, runtime="default", openjev)`. `modal_app` already calls them; a config picks its runtime with
  `[launch.modal] runtime = "<name>"` (default `"default"`).
- `src/s1/launch/base.py`: `Resources` (one GPU each) and `Launcher.submit(cfg, resources, s1_args, *,
  dry_run=False) -> str`. Fan-out is several `Resources`, not a list inside one.
- `src/s1/env.py`: everything in it (M1-M2 contract), including `resolve_path` and the `META_*` names.
- `roofline.spec_peaks(gpu) -> (bf16_tflops, fp32_tflops, bw_gbs) | None`.
- Record fields: nothing renamed. New fields only with a name prefixed by the benchmark or listed in `env.py`.

- Modal GPUs and the names nvidia-smi reports: L4 `NVIDIA L4`; A100-80GB `NVIDIA A100-SXM4-80GB`; H100 (pinned

  point and never mixes platforms on one roof.

  kernels in `meta`. Configs write model files as `$MODELS_DIR/...`.
- The 11 roofline models and their configs: `roofline_l4.toml` (qwen35-9b, jevk5-9b, qwen3-8b, olmoe, lfm2,
  granite: the SemIf letter-softmax readout), `roofline_l4_kev.toml` (kev-4b hybrid and qwen3: upstream code in
  `$MODELS_DIR/kev-code`), `roofline_l4_laya.toml` (laya english and multilingual: code and checkpoints under
  `$MODELS_DIR`), `roofline_l4_elephant.toml` (elephant-1: its own runtime). Weights of the first six are on the
  Modal volume; the rest are not yet.
