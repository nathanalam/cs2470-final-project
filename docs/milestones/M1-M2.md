# Milestones M1-M2: OpenJev on one H100, and trustworthy Modal measurements

Brief for every agent working on M1-M2. Read it whole before starting, along with `AGENTS.md`.
The full plan (all milestones, rationale) is the "Modal + Slurm Pipeline and GPU Sweep Plan" doc; this file is
what you need to act.

## Goal

- **M1:** `uv run s1 submit <cfg>` runs a config on Modal when its `[launch]` table says
  `orchestrator = "modal"`, and on Slurm when it says `"slurm"`, with nothing else changed. OpenJev runs on one
  H100 (TP=1, bf16, `max_model_len = 16384`) and its JEVal smoke and shape-sweep records land in `results/`.
- **M2:** the cluster profiling probe (`scripts/profiling_probe.sh`, `scripts/ncu_smoke.py`) runs on a Modal L4 and
  H100 with findings in `docs/profiling.md`; `roofline_l4.toml` on a Modal L4 is compared with the committed
  cluster L4 runs.

## Frozen contracts (do not change; ask the coordinator)

- `src/s1/env.py`: `orchestrator()`, `job_id()`, `git_commit()`, `log_dir()`, `models_dir()`, and the
  `META_*` / `INV_PLATFORM` field names. Hardware description goes in `meta`; only `invariants.platform = "modal"`
  is added, and only on Modal.
- `src/s1/launch/base.py`: `Resources`, `Launcher.submit(cfg, resources, s1_args, *, dry_run=False) -> str`.
- Environment variables: `SLURM_JOB_ID`, `MODAL_TASK_ID`, `S1_GIT_COMMIT`, `S1_LOG_DIR`, `MODELS_DIR`.

## Rules (hooks enforce the starred ones)

1. Keep `uv run ruff format`, `uv run ruff check`, `uv run pytest` green, and add no new `ty` diagnostics. The
   22 existing ones come from torch/transformers not being installed locally; the baseline is
   `.claude/ty-baseline.txt`.* A session in a worktree cannot stop until these pass.
2. Commit to your own branch with clear messages. Never push to `main`, never force-push.* Do not merge.
3. No Modal or GPU spend unless the command is in the approved ledger.* If you need a run that is not approved,
   stop and say exactly what command and why; the coordinator asks the user.
4. Never write a token or key to a file, config, record or commit message.* Modal auth comes from the user's
   `modal token set` or the `MODAL_TOKEN_ID` / `MODAL_TOKEN_SECRET` environment variables.
5. Do not edit `.claude/`, `AGENTS.md`, `CLAUDE.md` or another workstream's files.
6. Records: one run = one file in `results/`, never edited by hand (AGENTS.md rule 2). Workstreams A-E write no
   records.
7. When done, reply with: branch name, what changed, how you verified it, anything left open.
