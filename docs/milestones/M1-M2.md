# Milestones M1-M2: OpenJev on one H100, and trustworthy Modal measurements

Brief for every agent working on M1-M2. Read it whole before starting, along with `AGENTS.md`.
The full plan (all milestones, rationale) is the "Modal + Slurm Pipeline and GPU Sweep Plan" doc; this file is
what you need to act.

## Goal

- **M1:** `uv run s1 submit <cfg>` runs a config on Modal when its `[launch]` table says
  `orchestrator = "modal"`, and on Slurm when it says `"slurm"`, with nothing else changed. OpenJev runs on one
  H100 (TP=1, bf16, `max_model_len = 16384`) and its JEVal smoke and shape-sweep records land in `results/`.
- **M2:** the cluster profiling probe (`scripts/profiling_probe.sh`, `scripts/ncu_smoke.py`) runs on a Modal L4 and
  H100 with findings in `docs/profiling.md`; `roofline_l4.toml` on a Modal L4 is compared with the committed
  cluster L4 runs.

## Results (2026-11-08)

**M1: done.** OpenJev (pin `b4a89f58`, bf16, `max_model_len = 16384`) on ONE Modal H100 (`H100!`, TP=1) against the
4x A10G TP=4 cluster runs, same 200 JEVal questions and seed (`configs/openjev_jeval_smoke_h100.toml`):

| | 4x A10G, TP=4 (cluster) | 1x H100, 8 in flight | 1x H100, 1 in flight |
|---|---|---|---|
| accuracy / invalid | 77.6% / 6 | 78.1% / 6 | 77.6% / 6 |
| questions/s | 0.69 | 6.68 | 5.45 |
| mean / p90 latency | 11.7 s / 24.2 s | 1.22 s / 2.56 s | 0.19 s / 0.53 s |

Weights 51.1 GiB, KV cache 210,564 tokens (12.9x concurrency at 16k). Shape sweep
(`configs/openjev_shape_sweep_cache_h100.toml`, 0 invalid, 0 skipped): 2x faster than 4x A10G at the smallest point
(32 state tokens, 1 question: 58 vs 115 ms) and ~9-10x at realistic ones (2048 tokens, 32 questions, cache off:
5.8 s vs 58.7 s; cache on 1.6 s vs 15.9 s). Engine: vLLM 0.29.0 on the `nvidia/cuda:13.0.3-devel` image (FlashInfer
JIT-compiles its sampler and needs nvcc).

**M2: done, with a finding.** Probe: ncu (`--clock-control none`) and nsys work as a normal user on Modal L4 and H100,
DCGM is absent, both GPUs run power-capped under load (`docs/profiling.md`, "Modal"). Calibration
(`configs/roofline_l4_modal.toml`, six models): analytic intensity identical, accuracy identical (one question apart on
Qwen3.5-9B), measured memory-bandwidth ceiling identical (230 vs 231 GB/s), but the Modal L4 is **3-18% slower in GPU
time** (Qwen3.5-9B +18%, OLMoE +13%, LFM2 +9%, JevK5 +8%, Qwen3-8B +5%, Granite +3%) and its measured bf16 GEMM ceiling
is ~8% lower (54 vs 59 TFLOP/s). Repeated cluster runs agree within 0.3-0.9%, so this is a platform difference, not
noise. Consequence for M3/M4: do not mix Modal and cluster timings; use the Modal L4 as the L4 point of the GPU sweep
(records carry `invariants.platform = "modal"`). Roofline position (intensity, efficiency vs measured ceilings) is
close across platforms.
